Runbook 2: Destroy Infrastructure

Option A: GitHub Actions (has confirmation prompt)

# Go to:
# https://github.com/prateekpanjla-ltm/gcp_data_proc/
#   actions/workflows/gh-archive-destroy.yml
#
# Click "Run workflow":
#   environment: test
#   confirmation: "destroy"  (must type exactly)

Option B: Direct from laptop

# Authenticate as deployer
gcloud auth activate-service-account \
  --key-file=infrastructure/test-terraform-deployer-key.json

# Destroy phase by phase (reverse order):
cd infrastructure/github_archive/phase4_monitoring/terraform/layers/03_operational
terraform destroy -auto-approve \
  -var="project_id=beaming-glyph-489707-b8" \
  -var="environment=test" \
  -var="region=us-central1"

# Repeat for phase3, phase2, phase1...

What gets destroyed

  • Cloud Run Jobs + Services
  • Cloud Functions
  • Eventarc triggers
  • Cloud Scheduler jobs
  • GCS buckets (force_destroy = true)
  • BigQuery datasets
  • Artifact Registry repos
  • Service accounts + IAM bindings

What survives destroy

  • Terraform deployer SA (created outside TF)
  • Deployer key file (local disk)
  • Terraform state bucket
  • API enablements (disable_on_destroy = false)

Runbook 3: Identify & Clean Stale SAs

# 1. List all SAs in project
gcloud iam service-accounts list \
  --project=beaming-glyph-489707-b8 \
  --format="table(email, displayName, disabled)"

# 2. Find SAs active in the last 7 days (from audit logs)
gcloud logging read \
  'protoPayload.authenticationInfo.principalEmail:".iam.gserviceaccount.com"
   AND timestamp>="2026-03-12T00:00:00Z"' \
  --project=beaming-glyph-489707-b8 \
  --format="value(protoPayload.authenticationInfo.principalEmail)" \
  | sort -u > /tmp/active_sas.txt

# 3. Compare: find SAs with no recent activity
gcloud iam service-accounts list \
  --project=beaming-glyph-489707-b8 \
  --format="value(email)" | while read sa; do
  if ! grep -q "$sa" /tmp/active_sas.txt 2>/dev/null; then
    echo "STALE: $sa"
  fi
done
